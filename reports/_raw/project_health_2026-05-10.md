**Status: PARTIALLY FIXED, root cause still live.**

- `app/build.gradle.kts` line 95: `implementation(files("libs/sherpa-onnx-1.12.40.aar"))` — flat-file AAR only. No Maven coordinate for sherpa-onnx present.
- `app/libs/` contains only `sherpa-onnx-1.12.40.aar`.
- The hand-copied Kotlin wrapper source that WAS causing the duplicate (`app/src/main/java/com/k2fsa/sherpa/onnx/`) is NOW EMPTY — the 5 wrapper .kt files were displaced to `C:\Users\georg\Documents\GitHub\wim-android\.r8-displaced-sherpa-wrappers\` (FeatureConfig.kt, HomophoneReplacerConfig.kt, OfflineRecognizer.kt, OfflineStream.kt, QnnConfig.kt — all dated 2026-04-24).

**Diagnosis:** The R8 duplicate-class error (`com.k2fsa.sherpa.onnx.FeatureConfig` defined twice) was caused by: (1) flat-file AAR in `libs/` AND (2) hand-copied .kt files compiling the same classes under `app/src/main/java/com/k2fsa/sherpa/onnx/`. The .kt files have been moved out of the compilation path to `.r8-displaced-sherpa-wrappers/`. The `app/src/main/java/com/k2fsa/sherpa/onnx/` directory is now empty.

**What is currently broken:** The app source (`MoonshineEngine.kt`, etc.) still imports `com.k2fsa.sherpa.onnx.*`. Those classes now come exclusively from the AAR. Whether R8 still sees a duplicate depends on whether any of those displaced .kt files are still somehow included in the build. Given the directory is empty, the debug build should be fine — but the release R8 pass was blocked as of 2026-05-05. This needs a release build test to confirm the fix landed.
